# Browser IAM 5 contexts

The browser gateway accepts exactly one Carbon or Silicon account and organization from each Hook token exchange. A context has an opaque public ID, private encrypted tokens and its own optional existing Ting session. Production and every testing environment retain independent active and saved contexts. Adding another account or organization keeps other contexts; signing in again replaces only the matching account and organization in that environment.

The sidebar selects saved account/organization contexts through `POST /console/context?plane=…`. It never changes organization authority by editing `X-Org-Id`. Ordinary requests carry `X-Hook-Context`; live streams carry the same ID as `context`. The gateway checks it while holding the browser session lock, before refresh or upstream work. Stale tabs and pending feature approvals receive `409 session_context_changed`; reload and return to the original workspace before retrying. A different organization header receives `409 organization_context_mismatch`. Refresh must retain both actor and organization.

Frontend views remount on the context ID and receive a fixed context snapshot, preventing a pending mutation from adopting a newer account. Separate Ting feature approval retains idempotency keys on retry, remains scoped to that snapshot and requires a fresh review after a 412. Cancel closes the approval without changing accounts or approved grants. Existing Ting login and live delivery integration contracts are preserved.

Saved sessions from before this migration do not have a trustworthy context ID and are signed out locally on load. Users must sign in again; the gateway does not guess an organization from old multi-organization permissions. Signing out revokes only the selected context. Forgetting a connection revokes all contexts for that environment, without deleting the backend environment. An attached testing application's secret cannot silently replace an authenticated environment's authority.

Run verification from `web`: `npm test`, `npm run check`, and `npm run build`. Tests cover Carbon and Silicon contexts, same-organization accounts, cross-organization and testing isolation, encrypted persistence/restart, stale HTTP requests, live receiver isolation, immutable refresh/retries, and legacy-session invalidation. Live IAM 5 acceptance remains a deployment gate.
